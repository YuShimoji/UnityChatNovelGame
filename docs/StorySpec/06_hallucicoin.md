# 06 — HalluciCoin（ハルシコイン）

## 1. 定義
AIのハルシネーション（矛盾・参照欠損・語りの歪み）を「指摘」することで得られるトークン。
ただし増減は一部不透明にし、**評価指標のブラックボックス化**をテーマに接続する。

## 2. 性質：消費財ではなく到達権

### パワースター類比（マリオ64）
- マリオ64のパワースターは「使って消える通貨」ではなく、「集めることで新しい場所に行ける権利」
- ハルシコインも同様：**消費して減るのではなく、蓄積量が到達権を解放する**
- プレイヤーは「コインを何に使うか」ではなく「次の扉を開けるために何を見つけるか」を考える
- この設計により、「節約して溜める」戦略ではなく「世界を注意深く観察する」動機が生まれる

## 3. 獲得（設計方針）
- **序盤**：ログ内矛盾（露骨）で学習。Pyramidの曖昧な整合を見抜く練習
- **中盤**：認識の齟齬（ポスト真実的ナラティブの同化）で難度上昇
- **終盤**：合意の限界に到達。指摘の対象が「明確な嘘」から「構造的な歪み」に移行
- **「いつの間にか増えている」演出**（初回＝3節）：誰が評価したのか不明。プレイヤーの疑念を煽る

### 増加因果の候補（未確定 → `99_open_questions.md` 参照）
| 候補 | 概要 |
|------|------|
| A) 端末内部評価 | 不透明なスコアリング（ブラックボックス） |
| B) 仲間が裏で指摘 | 他の参加者が独自に検証している |
| C) AIが保険として配布 | モデル側のリスクヘッジ |
| D) 断片接触で増加 | 不可索引物への接触自体がトリガー |

## 4. 消費先（到達権としての運用）
- **サブスレッド解放**：注釈／追跡／偵察強化の各スレッドを開く
- **扉（ゲート）開放**：節末・イベントへの到達権
- 蓄積量の閾値で自動的に開く設計（「使う」UIではなく「到達した」通知）

## 5. UX演出
- **指摘時**：殴打音＋コイン散乱（小気味よさ。正しく指摘できた手応え）
- **増加通知**：控えめなバッジ表示（公共空間での使用を想定）
- **「いつの間にか」演出**：通知なしで数値が変化。プレイヤーが自分で気づく
- 音量は控えめにできる設計（羞恥耐性の一環）
