# SP-019: チャプター遷移体験

Status: DRAFT
作成日: 2026-03-18
カテゴリ: system/ui

## 目的

プレイヤーが「チャプターを完了し、次に進む」瞬間を体験として成立させる。
現状はEndDay→ダッシュボード→次カードクリックの機械的遷移のみ。
「進んだ」という達成感と「次への期待」を基盤能力としてシステム化する。

## 体験逆算: プレイヤーが感じるべきこと

### チャプター完了時
1. **達成感**: 「このチャプターでこれだけ進んだ」の可視化
2. **振り返り**: 発見した断片・矛盾・スレッドのサマリー
3. **引き**: 次チャプターへの手がかり/予告

### 次チャプター解放時
1. **解放の実感**: 新しいチャンネルが「開いた」ことの明確なフィードバック
2. **期待形成**: 次チャプターの雰囲気・テーマの予告
3. **連続性**: 前チャプターの知識が次に持ち越される確認

## 現状のフロー

```
EndDay N (最終Day) → SystemMessage("--- N日目 終了 ---")
  → CompletedChannelIDs に追加
  → Yarn ノード終了
  → プレイヤーが手動でダッシュボードを開く
  → HCゲート+前提チャンネル条件を満たしていれば次カードが Active
  → カードクリック → 次チャプター開始
```

問題点:
- チャプター完了の「瞬間」が存在しない (SystemMessage 1行だけ)
- 次チャプター解放が暗黙的 (ダッシュボードを開くまで分からない)
- チャプターの成果サマリーがない
- 前チャプターとの接続感がない

## 提案: 3段階遷移

### Phase 1: チャプター完了サマリー (MVP)

**トリガー**: EndDay で最終Day完了時 (dayNumber >= TotalDays)

**表示内容** (チャット内SystemMessage群として):
1. `--- Chapter {N} 完了 ---` (既存の日終了メッセージを置換)
2. サマリー行: `断片 {collected}/{total} | 矛盾 {found}/{total} | HC +{earned}`
3. NudgeSystem からの次ステップヒント

**実装範囲**:
- EndDayCommand 内の分岐拡張
- ProgressTracker.GetSnapshot() から数値取得
- 追加C#コード: ~20行

### Phase 2: 次チャプター解放通知

**トリガー**: CompletedChannelIDs 追加後、次チャンネルの条件を評価

**表示内容**:
1. SystemMessage: `新しいチャンネルが解放されました: {nextChannel.DisplayName}`
2. ダッシュボード自動表示 (1.5秒後) — プレイヤーが解放を視認できる

**実装範囲**:
- DashboardController に `CheckNewUnlocks()` メソッド追加
- EndDayCommand 完了後にコールバック
- 追加C#コード: ~30行

### Phase 3: チャプター間接続演出 (将来)

**対象**: 次チャプター開始時に前チャプターの知識を活用する場面

**要素**:
- 前チャプターで獲得した断片の一覧表示 (引き継ぎ確認)
- 前チャプターのスレッドの現状表示
- $has_topic_fragment_* 変数に基づくYarn分岐の視覚的フィードバック

**位置づけ**: SP-018 Phase 2 (チャプター間接続可視化) と統合

## Phase 1 の受け入れ条件

1. Ch1 EndDay 3 実行後に「Chapter 1 完了」+サマリーが表示される
2. サマリーに断片/矛盾/HC数が正確に反映される
3. NudgeSystem が次ステップを示す (例: "Ch2が解放されています")
4. 既存の EndDay 非最終Day挙動は変更なし

## Phase 2 の受け入れ条件

1. チャプター完了後に次チャンネル解放通知が表示される
2. 通知後にダッシュボードが自動表示される
3. HCゲート未到達の場合は通知を出さない (HC不足メッセージのみ)

## やらないこと

- サウンド演出 (SP-009 未着手)
- チャプター間アニメーション/トランジション
- チャプター選択画面の再設計
- リプレイ/やり直し機能

## エンジン基盤としての位置づけ

この仕様は個別チャプターのコンテンツではなく、全チャプター共通の遷移基盤である。
Ch1-Ch9 の全遷移で同じシステムが動作する。
Phase 1 は既存の ProgressTracker + NudgeSystem (SP-018) の自然な延長であり、
新規モジュール不要で EndDayCommand の拡張のみで実現可能。
