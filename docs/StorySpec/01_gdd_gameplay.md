# 01 — Game Design（Gameplay / Systems）

## 1. コア・ループ

```
1) チャットログを読む（情報の欠損・矛盾を観測）
2) 定型選択肢で問いを投げる（表層は幼弱だが、含意で介入可能）
3) AI／参加者の返答を評価（整合性・参照の成立）
4) ハルシネーション指摘 → ハルシコイン獲得（ただし増減因果は部分的に不透明）
5) コインでサブスレッド／偵察強化／扉を開ける
6) 新しい断片／偵察ログで層更新、次の節へ
```

### 探索の深層ループ（トピック分岐）
```
トピック発見 → 調査 → キーワード発見 → 無限に枝分かれするリンク
                                            ↓
                                    サブスレッド展開 → 新たなトピック
```
- 解決ではなく**参照の深化**が進行感を生む
- 各リンクが新たな疑問を生み、探索が自走する構造

## 2. プレイヤー操作
- 基本：読み進め／選択肢／指摘（タグ付け）／サブスレッド生成
- 主人公（バルナビー）の発話は制限される（端末機能が弱い＝デザイン制約を物語化）
- 操作の手触り：選択肢は幼弱に見えるが、含意（implicature）で介入可能

## 3. 分岐とリプレイ
- エンディング：単一（全解放で到達）
- 分岐：主にサブスレッド（寄り道）＝回収要素として機能
- 目的は"世界を変える"より、"終わらない議論を前へ進める"媒介
- 未到達でも物語は成立する（全回収は完璧主義者向けのボーナス）

## 4. サブスレッド（3種固定）
A. **注釈**：用語・背景・制度・AI挙動の短い解説
B. **追跡**：地名／機関名／出来事のリンク追跡（"参照の地獄"）
C. **偵察強化**：外出・探索の質を上げる（録音/撮影/採取の精度、行動指示）

### サブスレッドのトリガー
- 会話中のキーワードから自然発生（プレイヤーが気づく → 選択肢で追跡を選ぶ）
- 断片の照合で矛盾が検出された時
- 偵察で新しい物品・場所を発見した時
- ハルシコインで解放（到達権として機能）

## 5. 冒険アイテム（偵察成果物）
- **録音**：環境音、会話の断片（偵察強化Cで精度向上）
- **撮影**：標識、掲示物、施設外観（解像度は偵察強化に依存）
- **採取**：紙片、レシート、文書の物理コピー
- これらは断片インベントリに蓄積され、照合の素材になる

## 6. 証拠フォーマット（D混合／C軸）
- 主軸：テキスト断片（紙片・掲示・レシート等）
- 補助：環境音／静的画像（控えめ・不穏）
- 露悪・グロは排除。静的で薄い不穏

## 7. 難易度曲線
- 序盤：ログ矛盾（露骨）→ 指摘の学習
- 中盤：認識の齟齬（ポスト真実的ナラティブ）→ サブスレッド誘発
- 終盤：合意の限界→ 部分救出へ収束

## 8. ペーシング（FireWatch参照）
- **1節＝1日**。日常のルーティンと時間経過の感覚
- 各節の構成：目的 → 会話（観測） → 断片 → 偵察 → 層更新
- 生活の小報酬（無人コテージ、無人ショップ）を節の合間に挟む
- 急がせない。停滞も劇の一部として許容する

## 9. セーブ
- チャプター（節）単位オートセーブ

## 10. 失敗状態
- 明確なゲームオーバーは置かず、探索の滞留＝"停滞の劇"として扱う（ベケット的）
- 行き詰まった場合は注釈サブスレッドがヒントとして機能
