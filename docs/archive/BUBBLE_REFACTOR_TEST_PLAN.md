## 想定不具合リスト (注意深く確認すべきポイント)

### HIGH RISK

| ID | 想定不具合 | 原因の推定 | 確認テスト |
|----|-----------|-----------|-----------|
| R-1 | バブル高さ不足でテキストが下にはみ出す | `FinalizeBubbleSize` の `Canvas.ForceUpdateCanvases()` タイミングが1フレーム遅い。特にタイプライター効果との競合時 | TEST 4-3, 8-1 |
| R-2 | 名前行のリッチテキストタグが生テキストとして表示される | TMP の `richText` が無効、またはフォントアセットが `<size>` / `<b>` タグ未対応 | TEST 2-1, 2-2 |
| R-3 | 短いメッセージでバブル幅が0や負になる | `GetPreferredValues` が 0 を返す場合の下限ガードがない | TEST 4-1 |
| R-4 | セーブ復元時に名前が二重表示される | 復元パスでも `finalText` に名前を埋め込むため、保存データに名前が含まれていると重複の可能性 | TEST 12-2 |

### MEDIUM RISK

| ID | 想定不具合 | 原因の推定 | 確認テスト |
|----|-----------|-----------|-----------|
| R-5 | 角丸スプライトが黒い四角として表示される | テクスチャ生成の上下反転、Color32 の RGBA チャンネル順違い | TEST 5-1 |
| R-6 | 影が二重に付く (プール再利用時) | `ApplyBubbleVisuals` が呼ばれるたびに Shadow コンポーネントが追加される。既存 Shadow の存在チェックはあるが、プール返却時に Shadow が残る | TEST 5-4 |
| R-7 | `HLG.childForceExpandWidth = false` への変更で、アイコン付きバブルのレイアウトが崩れる | アイコン+バブルの合計幅がラッパー幅より小さい時の配置が変わる | TEST 2-4, 4-1 |
| R-8 | 画面回転やウィンドウリサイズ時にバブル幅が不正 | `Screen.width` は初回計算時の値。リサイズ後の再計算が走らない | TEST 4-2 (横幅変更後) |

### LOW RISK

| ID | 想定不具合 | 原因の推定 | 確認テスト |
|----|-----------|-----------|-----------|
| R-9 | `DisplayMode.IconOnly` のキャラクターで名前が表示される | コード上は IconOnly 分岐で `finalText = text` なので問題ないはず | TEST 2-1 |
| R-10 | システムメッセージの角丸が通常バブルと異なるサイズ | 同じ `GetOrCreateRoundedSprite()` を共有しているので同一のはず | TEST 6-2 |
