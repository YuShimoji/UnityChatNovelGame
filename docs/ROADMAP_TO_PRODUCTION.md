## ステップ

### Phase A: エンジン検証（〜数日）
**ゴール**: 既存エンジンが脚本執筆に耐えることを確認

1. **[手動]** ScenarioManager.m_AutoStartYarn = false に変更
2. **[手動]** ContentAuthoring シーンで再生 → ダッシュボードが表示されることを確認
3. **[手動]** ch1 チャンネルをタップ → Ch1 が再生されることを確認
4. **[手動]** 矛盾Phase2: ContradictionFeedbackController をセットアップ → 長押し+タップで指摘動作を確認
5. 問題があればバグ修正（Opus/Sonnet で即対応可能）

### Phase B: 第1章設計（並行可能）
**ゴール**: 第1章3節の骨格を確定

1. **[ユーザー主導]** 第1章の3日間それぞれの「何が起きるか」を決める
   - 現在の章レベル概要: 「媒介欠陥としての会話不全」「端末は壊れている」
   - 具体化: 各節の会話の流れ/登場キャラ/断片/矛盾ペア
2. **[対話]** キャラクターの第1章での立ち位置を確認
   - Pyramid: 最初に会話するAI。何を語るか
   - Marco/Bernardo: いつ・どう登場するか
   - Player(Barnaby): 選択肢のトーン・制約
3. **[対話]** 矛盾ペアの設計
   - 第1節: チュートリアル的な分かりやすい矛盾（1-2ペア）
   - 第2-3節: 段階的に難度上昇
4. **[AI補助]** ビート詳細を `03_chapter_beats.md` に追記（ユーザー承認後）

### Phase C: 第1節 Yarn 執筆
**ゴール**: 第1部第1章第1節の完全な Yarn スクリプト

1. 新規ファイル: `Assets/Resources/Yarn/Part1_Ch1_S1.yarn` を作成
2. ノード構成を設計（Phase B の結果に基づく）
3. 矛盾ペアの ContradictionPair SO を作成
4. ChannelData `ch1` を本番用に更新（または新規 SO 作成）
5. 実機テスト → 調整

### Phase D: 第1章残り + 振り返り
**ゴール**: 第1章(3節)の完成 + パイプライン検証

1. 第2節・第3節を同様に執筆
2. 第1章全体の通しテスト
3. 振り返り: 執筆パイプラインの改善点を `YarnEditingPipeline.md` に反映
4. 次の区切り: 第2章以降の設計 or サブスレッドUI実装 or アルケミー設計 を選択

## 脚本制作に「区切りよく入れる」タイミング

**最短**: Phase A (エンジン検証) 完了後 + P3 (第1節ビート) が固まったとき
→ Phase B の途中から Phase C に入れる。設計と執筆を交互に進められる。

**推奨**: Phase A + Phase B の第1節分が完了したとき
→ 1節分の設計が固まった状態で執筆に入る。最も手戻りが少ない。

**安全**: Phase A + Phase B 全体が完了したとき
→ 3節分の全体構成が見えた状態。ペーシングの一貫性を保ちやすい。
