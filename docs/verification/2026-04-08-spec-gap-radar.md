# 仕様漏れレーダー（実機待ち中の開発継続用）

更新日: 2026-04-08  
目的: Unity 通し確認ができない期間でも、**開発側**と**意思決定側**を分離して前進する。

## 方針（開発を止めない）

- 実機確認は SUBSEQUENT 発動時にまとめて行う。通常スライスでは仕様/実装準備を先行する。
- 見え方・表示バグ・演出は個別対応せず、**バッチ実装 + バッチ確認**に寄せる。
- 「仕様漏れ候補」は先に棚卸しして、HUMAN_AUTHORITY 判断ポイントを明文化する。

## A. 開発側（実機なしで進める）

### A-1. 仕様漏れ候補の棚卸し（優先）

1. SP-022 §6 を基準に、未実装/要仕様をテンプレ化
   - B型 Wiki 遷移（要仕様→要実装）
   - C型 成果物カードリッチ表示（要仕様→要実装）
2. `FEATURE_STATUS_AUDIT.md` の U/N/W 項目を「実装準備可能/検証待ち」に再分類
3. `spec-index.json` の `partial/draft/todo` を、次スライス候補へマッピング

### A-2. バッチ実装の受け皿を先に作る

- 対象を 1 つのバッチ仕様に集約する（例: `UI_BATCH_01`）。
- 含める候補:
  - タイピング位置/選択肢タイミング（U-3/U-4）
  - サブスレッド遷移のトランジション（ENH-011）
  - チャットバブル演出（ENH-010）
  - HalluciCoin 演出（ENH-012）
- バッチ仕様に「実装条件」「除外条件」「確認観点」を固定する。

### A-3. コード準備（挙動変更なし）

- フラグ/設定点の追加だけ先行し、既定値は現状維持（回帰リスク低減）。
- ChatController ステータスバールーティング TODO (FEATURE_STATUS_AUDIT W-6 参照)。
- 既存テスト（EditMode/PlayMode）を壊さない範囲で補助テストを追加。

## B. 意思決定側（HUMAN_AUTHORITY）

## B-1. 先に決めると開発が速くなる項目

1. B型 Wiki: 疑似リンク継続 or 本実装着手
2. C型 成果物カード: テキスト最小 or リッチUI
3. Day3 サブの密度: 維持 / 統合 / 遅延
4. Ch2 `EndDay` 粒度: 仕様で許容 or P0 実装で正す

## B-2. 決めないで進める項目（保留で可）

- BL-002（ポートレート）は視認性ボトルネック発生時のみ判断
- SP-018/019/020 の Phase 2+ は Ch2 進行を優先して後段判定

## C. 「まとめて実装・まとめて確認」運用

## C-1. 実装バッチ単位

- バッチ名: `UI_BATCH_01`（見え方/表示バグ/演出）
- 期間: 2〜3 セッションで実装集約
- ルール: バッチ中は UI 個別修正を追加しない（記録のみ）

## C-2. 確認バッチ単位

- 確認窓で一括実施:
  - ContentAuthoring 通し（Ch1 Day1→3）
  - Ch2 入口の表示チェック
  - PlayMode 8 件
- 結果記録:
  - `docs/verification/templates/SUBSEQUENT_playthrough_and_tests.md`
  - `docs/verification/templates/2026-04-10-playmode-8-results-TEMPLATE.md`

## D. 次の数回で見込まれる変化

### 1回目（設計固定）
- 仕様漏れ候補リストが確定し、実装順が固定される。
- 変更物は主に docs（コード変更は最小）。

### 2回目（バッチ実装）
- `UI_BATCH_01` の実装をまとめて投入。
- 目視不要の範囲（設定/分岐/ログ）を先行完了。

### 3回目（バッチ確認）
- 目視と PlayMode を一括実施し、P0/P1/P2 へ振り分け。
- 次プランで Ch2 前進に必要な最小P0だけ実装判断。
